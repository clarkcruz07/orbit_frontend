# Frontend decisions beyond SPEC.md

- **Unit test runner.** `npm test` runs `node tests/run-unit.mjs`, which lists `tests/*.test.mjs` and calls `node --test`. Node 20 has no glob support and Windows shells do not expand `tests/*.test.mjs`. TypeScript sources are loaded in tests by bundling with esbuild (shipped with Vite) via `tests/helpers/load-ts.mjs`.
- **Demo panel fills the email only.** `/auth/demo-users` never returns passwords (SPEC section 4), so a demo button fills the email field, focuses the password field and never signs in. The shared fictional password is in the README.
- **Demo panel gating.** It renders only when `GET /auth/config` reports `demo_auth: true` AND `GET /auth/demo-users` returns a non-empty list. With `demo_auth: false` the demo-users endpoint is not requested at all.
- **HR Administration route is not role-gated client-side.** The nav entry is visible to everyone and the page calls `GET /hr/dashboard`; a 403 renders "This page is restricted to HR Administrators". The backend stays the only control (it also audits `access.denied`).
- **"View Details / View All / Go to Directory / View All Cases"** are plain muted text (`MutedAction`, `title="Coming soon"`), not buttons or links; a source-guard test enforces it.
- **Search and bell.** Search is a disabled input with the tooltip "Search is coming soon". The bell opens a popover "No notifications yet - coming soon" and has no unread dot (the reference shows one; it would be dishonest).
- **Fictional demo data ribbon** sits in the eyebrow row, from `demo_notice` (tooltip) with fixed visible text "Fictional demo data".
- **Logo.** The supplied PNG carries "RTO CONSULTING" and is dark-on-transparent, so the Bluedge People lockup is recreated as inline SVG (handwriting font stack with `cursive` fallback + blue/yellow swoosh) in a light (sidebar) and dark (login) variant. `src/assets/bluedge_logo.png` is kept but unused.
- **Fonts.** Roboto latin 400/500/700 via `@fontsource/roboto` (local, no CDN). Roboto has no 600, so "semibold" is rendered at 500/700.
- **Contract tolerance.** Dashboard helpers accept month as name or number, birthday dates as "Jan 25" or ISO-like, `period` as `last_month` or free text, statuses as `in_progress` or "In Progress". Values come from the API; only labels are formatted.
- **Auth interceptor.** One shared in-flight refresh promise; a plain axios instance (no interceptors) performs `POST /auth/refresh` so it cannot recurse. A 401 after the single retry, a failed refresh, or a 401 with no refresh token calls `forceLogout()` (clears storage, redirects to `/login?next=...`; `/login` itself never loops).
- **Session restore.** Status machine `loading | authenticated | anonymous | unreachable`. Only 401/403 from `/auth/me` ends the session; network errors and 5xx show a "Try again" screen and keep the tokens.
- **Entra.** `@azure/msal-browser` is imported with dynamic `import()` only inside `entraLoginPopup()`, which is reachable only when `VITE_ENTRA_CLIENT_ID` is set. Otherwise the Microsoft button shows "Microsoft sign-in isn't configured in this local build." and no request is made. Token exchange is `POST /auth/entra {id_token}`.
- **Reimbursements hand-off.** Superseded: the placeholders are replaced by the real module (see "Reimbursements module" below).
- **HR Requests** besides Reimbursements: five muted "Coming soon" cards (no links, no buttons).
- **Responsive.** Sidebar is fixed at >= 1024px and a drawer below (hamburger, Escape, scrim, route change closes). Dashboard summary row: 5 columns, 3 below 1280px, 2 below 768px, 1 below 560px; the right-hand card moves under the grid below 1280px.
- **Browser tests** run against the built `dist/` served by a Node mock API (`tests/browser/mock-api.mjs`, binds a random 127.0.0.1 port, never 5173/5174/3000/8000). `playwright-core` is a devDependency; `PLAYWRIGHT_CORE_DIR` overrides the lookup; `CHROME_PATH` overrides the Chrome location.

## Reimbursements module

PLACEHOLDER WORKFLOW (not company policy). Approval never pays or posts anything; this is stated on the list, new, detail and reviewer screens.

- **Modes come only from `allowed_actions`.** `edit`/`upload`/`submit` -> employee editor, each control gated by its own action; `approve`/`reject`/`clarify` -> reviewer panel, each button gated by its own action; anything else -> read-only view. A source guard test forbids role-name literals and `.roles` in the detail/editor/reviewer/timeline/new components.
- **One deliberate role hint: list tabs.** `availableScopes(roles)` in `pages/reimbursements/logic.ts` (also used by Home) decides which tabs to offer (Employee: My requests; Manager/Finance: + Awaiting my review + All; HRAdmin: + All). It mirrors the backend `list_scopes_for` and is navigation only: the server still answers 403, a forced `?tab=review` falls back to "My requests" for accounts without it. Probing scopes with real calls was rejected because every refused probe writes an `access.denied` audit event.
- **No sidebar review badge.** It would need an extra `scope=review` call on every shell mount from a file outside this module's lane; not cheap, so none is shown (Home shows the real count instead).
- **Provenance in the editor** is computed live from the text in the box against the preserved `extracted_value` (Extracted / Edited by you / Entered by you / Not found; "Not entered" before any extraction exists). Missing values stay empty with "Not found on receipt - please enter" (or "Couldn't be read from the receipt - please enter" when extraction failed). A `flag` from the backend shows why an extracted value was dropped. "Low confidence" is shown below 0.7 (presentation only, never changes a value).
- **Server-side upload validation is authoritative.** The accepted types/size from `/reimbursements/config` are only a hint under the drop zone and in the file input's `accept`; nothing is blocked client-side, 4xx messages are shown inline with "Nothing was stored."
- **Unsaved edits are saved first** before an upload or re-extraction (otherwise applying the server response would discard them). If that save fails the upload is not started.
- **PATCH sends only changed fields** (cleared box -> `null`) plus the `version`. A 409 (save, upload, extract, submit, decision) reloads the latest request and shows a banner that unsaved edits were discarded.
- **Submit** needs the explicit checkbox ("I have checked these values against the receipt."), pre-checks the four required values and the receipt locally for friendly feedback, then POSTs `confirm_fields:true`; server `missing_fields` / `field_errors` / `confirm_required` are mapped next to the fields. Optional: tax and reference.
- **Receipt preview/download** go through the Bearer-token client as blobs (`URL.createObjectURL`, revoked on cleanup); images render inline, PDFs show a tile plus a download button. No token is ever in a URL, storage or HTML.
- **Audit trail noise.** Loading an image preview calls the download endpoint, so the backend records `reimbursement.receipt_downloaded` ("Receipt viewed or downloaded") on every page view by anyone. Shown honestly; PDFs only record one when someone clicks download. If this is too noisy, the backend could stop auditing previews (a backend decision, not changed here). The audit list names actors by: "You", the decider's name (from `decisions[]`), the employee's name for owner actions, otherwise the audit roles (the audit API carries no names).
- **Read-only "Extracted vs final"** table shows final value, source ("Edited by employee" etc.), low-confidence badge and the originally extracted value; dates and amounts are formatted there (raw values stay in the editor inputs).
- **Reviewer confirmation** is an inline confirm box (not `window.confirm`); reject/clarify stay disabled until a comment exists (max 2000, counter). After a decision the page refreshes from the response and the audit trail reloads.
- **Home** cards use `scope=mine` (counts by status + latest 3) and, only when the account has a review queue, `scope=review` (count + latest 3 + link to `?tab=review`); otherwise a muted note. Each card has its own loading, error (with retry) and empty state.
- **Tests.** Unit: `reimbursement-logic`, `reimbursement-api` (stub adapter on the real axios instance), `reimbursement-source-guard`. Browser: `reimbursements.spec.mjs` (mock API, `mock-reimbursements.mjs` forces allowed_actions/errors/extraction results) and `e2e-real.spec.mjs` (real backend via `real-backend.mjs`: random port 8101-8199, in-memory DB, demo auth + demo OCR only through the child's environment, temp storage, a Node server that serves `dist` and proxies `/api`; torn down with `taskkill /T`). The demo password is read from `backend/.env.example` (not any `.env`). `load-ts.mjs` got an esbuild `require` banner so axios can be bundled for node tests; the old source-guard test no longer lists the deleted placeholders file; the old "Reimbursements routes are placeholders" browser assertion became "opens the real list".
- **Known limitations.** No pagination on the list (the backend returns up to 500); no search; the mock-API list scoping is simplified; the screenshot test overwrites `docs/screenshots/*` each run; real Gemini extraction is untested by design (provider stays `demo`).

## Addendum 2: Directory, Calendar, My Profile, search, notifications, responsive pass

- **Route names.** The sidebar keeps its paths (`/my-profile`, `/company-calendar`); `/profile` and `/calendar` are redirects to them, so the reference nav order and every existing link/test stay valid. New routes: `/directory`, `/directory/:employeeId`. No new sidebar item.
- **HR-only directory fields come from the response, not a role.** `employment_type` / `start_date` / `status` are shown (and the employment-type filter offered) only after the server has returned them; the flag is sticky so the filter survives an empty result. A forced `?type=` for someone who may not use it gets a 403 from the server, the filter is dropped from the URL and a notice says so. A source guard forbids role literals and `.roles` in all new pages (My Profile only *displays* the server's `roles` list).
- **Directory state lives in the URL** (`q`, `department`, `type`, `page`): Back/Forward and "Back to directory" from a profile restore the same filtered page; a stale page number falls back to page 1. 20 per page, search debounced 300 ms, table >= 860 px, cards below.
- **Header search** is a WAI-ARIA combobox (listbox of option groups), 250 ms debounce, abortable (stale answers dropped), min 2 / max 64 characters checked on the client too, People + Requests from `GET /search`, Pages filtered locally from the nav plus the Employee Directory. 400/401/429/5xx show fixed, polite wording (never the server text). Escape closes the popup, then clears, then (phone) collapses. On <= 640 px it is an icon that expands to a full-width field; the popup is anchored to the header so it never leaves the screen.
- **Bell**: dot only when `unread_count > 0`; list newest first with relative times (`lib/dates.ts`, injectable clock); click marks read optimistically then opens the link (only same-origin in-app paths are followed, `lib/notificationsLogic.ts`); a failed mark-read says so and re-syncs from the server. Polls every 60 s while the tab is visible and refreshes on window focus / when the tab becomes visible. A notification without a link is still markable and goes nowhere.
- **Calendar**: month key in `?month=`; prev/next are disabled at +/-12 months (the server rule, with an honest tooltip) and a URL beyond the limit is clamped before any request; week starts on Sunday; holidays gold, birthdays blue, your own birthday solid violet; birthdays never show a year; grid at >= 641 px, agenda list below.
- **Personal Dashboard** gets "Upcoming holidays" and "Upcoming birthdays" from `/calendar/upcoming` (each with loading / error+retry / empty states).
- **Mobile drawer** now: closed drawer is `visibility:hidden` (not tabbable), opening moves focus to the first link, Tab/Shift+Tab wrap inside, Escape / scrim / route change close it and focus returns to the hamburger.
- **Touch targets** are >= 44 px at <= 768 px for hamburger, search, bell, profile, every `.btn`, form inputs/selects and tabs. The header search outline is now an inset shadow (not a border) so the input can fill the control height; desktop looks the same.
- **Browser tests are hermetic.** `npm run test:browser` always rebuilds `dist/` with the Microsoft sign-in variables blanked through the process environment (which wins over any `.env`, which is never read), because a locally configured Entra client id otherwise changes the login page and breaks the "Microsoft sign-in isn't configured" test. `--no-build` reuses an existing dist.
- **Existing assertions that legitimately changed** (placeholders became real): app.spec "HR Administration renders ..." (one real link, `Go to Directory`), "HR Requests ..." (two links: Reimbursements + Browse the directory), "other pages and 404" (Company Calendar removed from the placeholder list), the old "header: search is honestly disabled" test (replaced by `header.spec.mjs`), and source-guard.test (HR Requests link count, `Go to Directory` is the one real link on the dashboard).
- **Test files.** Unit: `addendum-api`, `dates`, `calendar-grid`, `search-logic`, `people-notifications-logic`, `addendum-source-guard`. Browser (mock): `directory-profile-calendar`, `header` (search, bell, drawer), `responsive-all-routes` (19 routes x 5 widths + an audit self-check), mock module `mock-new-endpoints.mjs` (hooked into `mock-api.mjs`; `state.newApi.*` flags force errors, delays and "now"). Browser (real backend): `e2e-real-addendum.spec.mjs`.
- **Known limitations.** Notifications poll (no push); search results are not highlighted/paginated (max 8 per group by contract); the calendar shows each day's chips without a "+N more" collapse; the directory has no sorting controls (server sorts by name).

## Modules

Every module is a folder `src/modules/<name>/` with a `routes.tsx` that `src/modules/registry.ts` discovers automatically (no central route list to edit). Module-specific frontend decisions live next to the code (`src/modules/peoplemgmt/DECISIONS.md`, `src/modules/timesheet/DECISIONS.md`); backend rules per module are in `backend/DECISIONS_<name>.md`. Shared rules for all modules: the server is the only authority (a hidden button is never the control; pages use the `allowed_actions` the API returns), a request the caller may not see looks like "not found", plain wording for errors (never server text for 401/429/5xx), 44 px touch targets at 768 px and below, tables become cards on phones, and every list/detail has loading, empty and error states.

- Settings: the Catalogs tab links to Holidays and People (HR only) and the Users tab links to "Manage people". `ROLES_NOTE` in `settings/logic.ts` now says roles are set by HR on the People pages or by configuration (it used to say roles cannot be changed in this app); its three tests were updated with it.
- Department filter on the People list is a client-side workaround (the API has no department parameter): it asks for `q=<department>`, reads up to 10 pages of 50, keeps exact matches and pages locally, with a note above 500 matches.
