# People management + Holidays admin (frontend): decisions and deviations

Contracts: `docs/api/peoplemgmt.md`, `docs/api/holidays.md`. Backend notes: `backend/DECISIONS_peoplemgmt.md`. Routes (auto-mounted by `modules/registry.ts`, no sidebar entry): `people`, `people/new`, `people/import`, `people/:employeeId`, `settings/holidays`. HR reaches them from Settings (Catalogs tab: "Holidays" and "People"; Users tab: "Manage people").

- **The server is the only control.** The module never reads the signed-in user or a role name. Every refusal is the server's status: 403 turns a page into "not available", 404 into "can't find that person". Pages that open with a form and have no read of their own (`people/new`, `people/import`) ask the server once through the same HR-only list route (`useHrAccess`); only a 403 means "denied", any other failure lets the page open and the real answer comes with the first save.
- **Guard rails are shown, never pre-judged.** "Save roles" is not disabled for yourself or for the last HR administrator: the server answers 403 ("You cannot change your own roles") or 409 `last_hradmin` and its own sentence is shown (guard-rail codes use the server's `detail`, other statuses use fixed friendly wording so server internals never leak).
- **Account facts come from the server's `account` object** (`has_account`, `can_sign_in`, `source`, `disabled_reason`): badge (No account / Can sign in / Sign-in off / Deactivated), the "no password, Microsoft sign-in only" explanation, and which sign-in button exists (turn off / switch back on / allow). A deactivated account has no switch: the page says to reactivate. The e-mail box is locked for accounts whose `source` is `entra_bootstrap` or `demo` (the server's 409 `email_managed` is shown too, so the lock is a convenience).
- **Roles.** `Employee` is shown always on; Manager / HR Administrator / Finance are checkboxes; the whole set goes to `PUT .../roles`. Demo accounts come back from the API as e.g. `["HRAdmin"]` (without `Employee`); the page displays `Employee` first anyway because the contract says it is always present.
- **Deactivate** opens an accessible dialog (focus moves in, Tab stays inside, Escape and Cancel close it, focus returns to the button) listing the consequences. A 409 `has_direct_reports` switches the same dialog to a manager picker (`reassign_reports_to`); 409 `last_hradmin` and 422 messages stay inside the dialog. Reactivate and "turn off sign-in" have their own short confirmations.
- **Manager type-ahead** uses the normal directory search (any signed-in user may call it), 250 ms debounce, aborts stale answers, and offers only people whose `status` is not `left` (HR gets `status` from the directory); the person being edited is excluded. The server still checks cycles and left people (422 on `manager_id`).
- **Department filter has no server parameter.** The list asks the server for the department text (`q=<department>`, 50 per page, at most 10 pages) and keeps exact department matches that also contain the typed search text (literal, like the server), then pages locally. If more than 500 people match the department text it says so. Department names come from the directory's `departments`.
- **CSV import**: always "Check file" first (dry run). "Import N people" appears only after a dry run that would create at least one person; invalid and skipped rows are simply left out (and the page says so). Client hints (over 1 MB blocks the check; empty file blocks; not `.csv`, missing header names and "about N rows" only warn) read nothing but the file name, size, header names and a line count. Cell values are never kept or shown; the report shows only what the API returned (row number, result, reason, per-field messages). The template is fetched as a blob through the authorised client (no token in a URL).
- **Holidays**: HR asks for `include_inactive=true`. When the response says `demo: true` (gate open and no active holiday), the page also reads the plain list to show the fictional demo holidays read-only (they have no ids) with a note that adding the first active holiday replaces them. With the gate closed an empty list says "no day is treated as a holiday". One-offs of other years that the server returns to HR (`date_in_year: null`) are counted in a note, not listed; saving a one-off into another year jumps to that year. The usage note says the calendar and leave day-counting use the list and that existing leave requests are NOT recalculated (repeated in the delete dialog).
- **Settings edits (narrow).** `CatalogsTab.tsx` appends two entries (Holidays, People) from a local list; `logic.ts` (CATALOGS, ROLES_NOTE) was not touched. `UsersTab.tsx` gets a "Manage people" link and a one-sentence note. The Settings roles note (`ROLES_NOTE`: "cannot be changed in this app") was stale because HR can change roles on the People pages; it was reworded in the final pass (`settings/logic.ts` and its three tests).
- **Not built / limits.** No sort controls (server sorts by name); no bulk actions; the people list shows 20 per page; the department filter is a client-side exact match over at most 500 server matches; pending leave/timesheet items of a person who leaves are not touched (backend decision); no e-mail or invitation is sent (backend decision).
