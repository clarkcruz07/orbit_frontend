# Attendance & Timesheet (frontend module) - decisions

Contract: `docs/api/timesheet.md`. Placeholder rules, not company policy; approval has no pay effect (said on every tab and in the decision panel).

- **One route, six tabs, URL-synced** (`/attendance?tab=`): `today` (default, no param), `timesheet`, `corrections`, `approvals`, `team`, `hr`. Notification deep links land on `?tab=timesheet&week=..&employee_id=..` and `?tab=corrections&id=..`. A link with the viewer's OWN `employee_id` opens their own sheet. A tab that is not offered but is requested by URL still renders; the server answers 403/404 and the page says "not available" (no data, no probing).
- **Which tabs are offered.** The HR tab comes from the server's own flag (`GET /timesheet/codes` -> `can_manage`), no role. Approvals (Manager or HRAdmin) and Team (Manager) come from `availableTabs(roles, canManageCodes)` in `logic.ts`: a navigation hint only, the same trade-off as `availableScopes` in the reimbursements module, because probing `review`/`team` would write an `access.denied` audit event per refusal and the API has no "may I review?" flag. Role names appear only in that one function; a source guard enforces it. Every button inside a tab is driven by `allowed_actions` (clock_in / clock_out / request_correction, edit / submit / recall / approve / reject, cancel).
- **Server is the truth for time.** The running timer is `server now - clock_in` plus the seconds since the status response (`elapsedMs`), so a wrong laptop clock changes nothing. The page asks the server again when the local timer passes 16 h; "flagged" is only shown from the server's `needs_correction`. Times are shown in the company time zone from the payload (`Intl`, unknown zone falls back to UTC).
- **Flagged session** (open > 16 h, never auto-closed): the card explains it in plain words, shows no clock buttons (the server allows only `request_correction`), and links to a correction form prefilled with the day and the punch's `session_id` (approving resolves the punch). The month view marks the day "Needs correction".
- **Corrections** never overwrite punches: the month view shows the effective times plus "Original punches: ...". Early checks mirror the server (past day, 60 days, out after in, 16 h span, reason 1..500); the server's `code` is mapped next to the field. One pending request per day is explained from the 409.
- **Weekly grid.** Text inputs (`inputmode=decimal`, comma accepted) validated per cell: invalid / 0..24 / quarter-hour; the day total <= 24; one row per code (a code already on the sheet is not offered), 20 rows. Save and Submit are disabled while invalid and the reasons are listed. Submit saves unsaved edits first (two calls, in order). Future weeks can be saved but the Submit button is not shown (`is_future_week`). Submit with no hours is refused locally. Unsaved hours: week navigation asks before discarding, and `beforeunload` warns. A stale `version` (409) reloads the latest sheet and says the edits were discarded; other refusals keep the typed values.
- **Phones (<= 640 px).** The same data is rendered as one stacked card per day (one structure at a time, via `matchMedia`, so test ids are unique); tables become cards. All controls are >= 44 px at <= 768 px.
- **Review.** Approvals lists sheets and corrections (filters carry counts) and opens them in the same viewers: a report's sheet is read-only with the decision panel when `allowed_actions` has approve/reject. Reject needs a comment (checked locally; the server's `comment_required` is mapped too). A 409 on a decision reloads the object and says why. Team: hours per direct report (read), attendance by day, and a report's month (read; audited server-side). HR: counts only (no names) plus the code catalog (create, rename, billable, deactivate). Deleting codes is not offered (browser CORS has no DELETE; a code in use is deactivated).
- **Decision comments and reasons** are shown only to people the server lets read them; the client never puts them in a URL, storage or log.

## Tests
- Unit: `tests/timesheet-logic.test.mjs` (week math, durations, time zones, cell parsing/validation, totals, dirty tracking, tabs, error mapping, correction checks, deep links), `tests/timesheet-api.test.mjs` (exact requests, PATCH not PUT, no DELETE), `tests/timesheet-source-guard.test.mjs` (no dead buttons, no role-name checks, allowed_actions gating, links).
- Browser, mock API (`timesheet-mock-api.mjs`, self-contained): `timesheet-ui.spec.mjs` (UI states), `timesheet-responsive.spec.mjs` (5 widths x 18 states + audit self-check).
- Browser, real backend: `e2e-timesheet.spec.mjs` via `timesheet-real-stack.mjs`, which starts the backend through `timesheet-clock-server.py` so the injectable clock (`app.state.timesheet_now`) can be moved from the test (offset file) - used for the 16 h flagged-session path (clock +25 h).
- `TS_DIST_DIR` points the three timesheet browser suites at a private build instead of the shared `dist/`.
- Screenshots: `node tests/browser/timesheet-screenshots.mjs` -> `docs/screenshots/timesheet-*.png` (mock data, fictional).
